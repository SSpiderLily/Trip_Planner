    04 / PERSISTENCE

    数据留在哪里，任务如何结束？

    关闭页面、刷新、重启后端是不同事件。先看保存位置，再看任务状态。

    SQLite 的三张表

    tasks

    一份请求对应一个 task_id

    status · request_data · 起止时间 · 错误摘要
    1 → 0..1
    task_results

    保存已成功生成的完整行程 JSON

    task_id 外键 · result_data
    tasks 1 → N
    spans

    生成过程中的各次调用

    span_id · parent_span_id · 输入输出 · 时间 · 用量

    spans 用 parent_span_id 形成调用树。删除任务通过外键级联清理结果和调用记录；没有独立的景点、酒店、编辑历史表。

    任务状态不是行程质量评分

    校验 / 忙碌拒绝
    未启动规划    或accepted
    登记请求    →running
    后台执行    →succeeded
    校验通过且保存成功

    failed：规划异常或结果保存失败。状态查询仍可返回 HTTP 200，结果接口返回 HTTP 409。

    interrupted：后端再次启动时，将数据库内未结束的任务标记为中断，不自动重跑。

    成功状态与保存结果在同一事务中写入。观测写入失败只标记记录不完整；结果写入失败不能显示成功。默认保留已结束任务 7 天，容量治理目标 200 MiB；活动任务保留。

    如何阅读源码，如何在本地打开本页？

    通过项目根目录的本地 HTTP 静态服务打开本页，函数按钮会按需读取对应 .py、.ts、.vue 文件并定位符号。只读取页面列出的代码文件，不读取配置密钥、数据库或第三方服务。

    直接用 file:// 打开时，浏览器可能阻止源码读取；此时可复制文件路径与符号，在编辑器内搜索。代码路径相对于项目根目录，不依赖 GitHub 分支或固定行号。

    如果本地没有静态服务，可在项目根目录执行 python3 -m http.server 8765 --bind 127.0.0.1，然后访问 http://127.0.0.1:8765/docs/project-overview.html。这是文档预览，不需要启动业务服务。
