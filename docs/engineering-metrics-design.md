# 单任务工程指标设计

更新日期：2026-09-28

状态：本地实现已完成替代依赖、构建和浏览器样例验证；真实供应商 Token 返回仍待实际任务联调。本文保留第一版统计口径与验收依据。

## 目标与文档分工

在现有规划观测页查看单次任务的状态、耗时、模型与工具调用、Token 消耗。工程执行成功不代表行程满足用户需求。

本文记录工程指标的已实现范围、统计口径与待验收事项；业务体验目标见[旅行规划体验优化需求](trip-planning-requirements.md)，稳定业务规则见 [CONTEXT.md](../CONTEXT.md)，实际使用说明见 [README](../README.md)，实施证据归入[学习日志](learning-log.md)。

## 已确认范围

- 整合 `/observability`，共用左侧任务列表、状态筛选与分页；右侧切换“工程指标”和“调用记录”。
- 只看单任务，不做跨任务汇总、P50/P95、批量评测、版本对比、评分或达标判断。
- 成功、失败、中断任务都展示已有指标；运行中提示“任务结束后可查看”，不实时刷新指标。现有调用记录刷新机制保留。
- 选择已结束任务默认打开工程指标；选择运行中任务默认打开调用记录。
- 记录供应商实际返回的 Token，不计价，不展示费用卡片。
- 使用概况卡片与简单明细表，不增加图表或首次结构校验通过率。

## 页面内容

| 区域 | 展示内容 |
| --- | --- |
| 任务概况 | 状态、总耗时、记录完整性、失败阶段及错误摘要 |
| 模型与工具统计 | 调用总数、成功／失败／中断次数、成功率 |
| Token 卡片 | 输入、输出、总 Token，采集覆盖情况与缺失提示 |
| 模型明细 | 按候选搜集、行程安排、行程修改角色分组，展示调用次数、状态统计、成功率、累计耗时和 Token |
| 工具明细 | 按实际工具名称分组，展示调用次数、状态统计、成功率和累计耗时 |

完整模型消息与工具返回仍在调用记录查看。角色归属依据 Span 父子关系；旧角色保留可识别名称，无法归属的调用单列，不丢弃。工具列表由实际记录生成，不限制为当前六种工具。页面说明“工程指标不代表行程业务质量”。

## 统计口径

### 状态与调用

- 沿用任务服务实际状态，生成并保存结果表示工程执行成功；持久化异常不能被指标页解释为成功。
- 调用次数按应用层模型／工具 Span 统计，失败、重复和修复调用全部计入；缓存命中不算外部调用。未采集的 SDK 内部重试不宣称已覆盖。
- 成功率 = 成功次数 ÷（成功次数 + 失败次数）。中断单列；分母为零显示“暂无数据”。有中断或缺失时注明“基于已记录且结果明确的调用”。
- 模型正常获得响应算调用成功，后续 JSON／Schema 校验失败不改写为模型请求失败。
- 工具正常返回且无工具业务错误算成功；正常空返回仍算调用成功，不能据此断言获得有效业务信息。
- 终态任务若仍有未结束的调用记录，单列状态未确定，不假定成功或失败，不静默丢弃。

### 耗时

- 任务总耗时使用任务接收到终态的创建、结束时间戳，不累加 Span。
- 中断任务缺少准确结束时间时显示“未知”，不以重启发现中断的时间替代。
- 模型／工具累计耗时只加总对应调用自身有可靠起止时间的 Span，不叠加角色和规划父 Span；累计调用耗时不等于任务墙钟耗时。
- 部分调用缺少结束时间时，已知耗时标注不完整，不冒充全部耗时。

### Token 与覆盖情况

- 按调用保存并汇总供应商实际返回的输入、输出、总 Token；不根据字符数估算，缺失不填零。
- 展示“已记录 5/6 次调用”等覆盖信息，分母为已记录模型调用总数。缺少任意调用用量时，合计标注“已知用量，用量不完整”。
- 字段部分缺失时分别保留已知值并提示，不把该调用当作完整采集。输入、输出均存在时可加总；缺任一项不伪造完整总量。缓存等细分字段不重复叠加到总 Token。
- 历史任务无用量时显示“未采集”，不反推历史消耗。
- 失败调用已取得用量时仍计入；未返回用量不意味着没有消耗。
- 观测本身不完整时，覆盖比例仅针对已记录调用，不能证明全部请求均已采集。

## 已实现功能与代码位置

以下依据 2026-09-28 本地代码与测试复核；服务器部署及真实供应商用量仍需分别验收：

| 功能 | 实现位置与行为 |
| --- | --- |
| 非流式 Token 采集 | [llm_service.py](../backend/app/services/llm_service.py) 的 `UsageAwareLLM.invoke_with_usage()` 从同一次模型响应读取文本与 `usage`，普通 `invoke()` 仍返回文本；未修改依赖包，也不额外发请求。 |
| 用量规范化与记录 | [observation_service.py](../backend/app/services/observation_service.py) 将供应商 `prompt_tokens`、`completion_tokens`、`total_tokens` 映射为调用用量元数据；不通过消息正文推算。 |
| 数据库存储与兼容 | [task_repository.py](../backend/app/services/task_repository.py) 为 Span 增加可空的 `input_tokens`、`output_tokens`、`total_tokens` 数值列，启动时迁移旧库；历史缺失值保持未知，凭据脱敏规则保留。 |
| 单任务聚合 | [metrics_service.py](../backend/app/services/metrics_service.py) 计算任务耗时、调用状态与成功率、用量覆盖、角色和工具明细；只读取摘要及元数据，不依赖完整消息。 |
| 只读接口 | [trip.py](../backend/app/api/routes/trip.py) 提供 `GET /api/trip/tasks/{task_id}/metrics`；[task_service.py](../backend/app/services/task_service.py) 复用有效任务状态，运行中返回 `409 / METRICS_NOT_READY`，任务不存在返回 404，指标读取失败返回 `503 / METRICS_UNAVAILABLE`。 |
| 观测页与入口 | [Observability.vue](../frontend/src/views/Observability.vue) 实现双视图、概况卡片和明细表；首页入口已更新。任务与视图保存在 URL，显式 URL 视图优先于默认选择，任务结束时不强制切走调用记录。 |

数据边界继续遵循：

- 采集和观测保存失败沿用记录不完整机制，不改变规划业务结果。
- 只统计该规划任务执行期间关联的调用。业务需求文档中的结果页按需交通查询属于独立请求，未来接入后不能追加到已结束规划的指标。
- 沿用现有记录保留与清理策略，不承诺永久报表留存。

## 验收清单

- 成功、失败、中断可查看指标；运行中不展示实时指标，调用记录保持可用。
- 默认视图符合任务状态，切换任务不残留上一任务数据。
- 成功 8、失败 1、中断 1 时显示 10 次调用、已知结果成功率约 88.9%；分母为零显示暂无数据。
- 工具空返回、业务报错、模型正常响应但结构错误的统计符合定义。
- 父子 Span 不重复计时，中断结束时间未知，部分耗时明确提示。
- 模型角色归属正确，修复调用计入，无法归属的历史记录可见。
- Token 全量、部分字段缺失、部分调用缺失、全部未采集及旧数据库均正确处理；未知不显示为零。
- 用量不会误脱敏，凭据脱敏没有弱化，不额外保存完整敏感模型响应。
- 观测不完整、终态保存失败、任务已清理有准确提示；指标查询失败不表示规划失败。
- 通过后端针对性测试、前端构建和浏览器检查；故障用替代依赖验证，不为指标测试额外消耗真实模型额度。
