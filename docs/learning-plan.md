# HelloAgents 智能旅行助手学习计划

更新时间：2026-09-22

## 学习目标与范围

以这个旅行助手为实践项目，重点掌握后端和 Agent 开发：能够解释一次旅行规划请求如何经过接口、业务逻辑、模型和外部工具，最终形成可校验的行程；能够独立修改流程、处理失败并验证效果。

建议精力分配：后端 40%、Agent 45%、部署与前端配合 15%。比例用于确定优先级，可随实践调整。

- 后端：FastAPI、数据契约、配置管理、服务职责、异常处理、同步与异步、测试。
- Agent：LLM 调用、工具调用循环、MCP、上下文、结构化输出、多 Agent 编排、效果评估。
- 部署与前端：掌握运行、联调和排障所需知识，支持验证后端与 Agent。

重点深入后端接口开发、Agent 与工具调用、可靠性与评估三个阶段。各阶段按验收结果推进，不设固定周数。

## 分阶段学习与验收

### 阶段 1：理解请求完整链路

**学习内容**：HTTP 请求与响应、FastAPI 路由、Pydantic 数据模型、各层职责。

**代码入口**：`frontend/src/services/api.ts`、`backend/app/api/main.py`、`backend/app/api/routes/trip.py`、`backend/app/models/schemas.py`、`backend/app/agents/trip_planner_agent.py`。

**实践任务**：沿“提交旅行需求 → 参数校验 → 调用 Agent → 外部工具 → 返回行程 → 页面展示”追踪实际函数，记录输入、输出和错误传递方式。区分代码中的真实行为与提示词描述的预期行为。

**验收标准**：能画出调用链，解释每层职责，并根据一次失败请求的响应与日志定位出错层。

### 阶段 2：后端接口开发（重点）

**学习内容**：参数校验、响应契约、配置管理、路由与服务划分、异常与超时、同步与异步。

**代码入口**：`backend/app/config.py`、`backend/app/models/schemas.py`、`backend/app/api/routes/`、`backend/app/services/`。

**实践任务**：选择一个实际接口问题，先明确正常输入、非法输入和外部服务失败时的预期行为，再做小范围修改。理解长时间生成请求是否阻塞其他请求，以及超时如何逐层传递。

**验收标准**：能独立增加或调整一个接口；用有针对性的验证覆盖正常、参数非法、外部调用失败场景；说明路由、服务和配置各自承担什么职责。

### 阶段 3：LLM 调用基础

**学习内容**：消息角色、上下文、模型参数、Token 与成本、超时、结构化输出和数据校验。

**代码入口**：`backend/app/services/llm_service.py`、`backend/app/config.py`、`backend/app/agents/trip_planner_agent.py`、`backend/app/models/schemas.py`。

**实践任务**：用最小示例单独调用模型，理解实际发送的消息结构；将返回内容转换为业务模型，观察缺字段、格式错误和内容不合理的区别。记录耗时及可获得的 Token 用量，无法获得时明确标注。

**验收标准**：能独立完成模型调用与结果校验，解释提示词约束和程序校验各自的作用；日志不包含密钥或完整敏感响应。

### 阶段 4：Agent 与工具调用（重点）

**学习内容**：模型决策与程序控制的边界、工具描述、参数解析、工具执行、结果反馈、循环终止条件、MCP 的职责。

**代码入口**：`backend/app/agents/trip_planner_agent.py`、`backend/app/services/amap_service.py`，以及当前安装版本的 HelloAgents 中相关实现。

**实践任务**：跟踪一次景点、天气或路线工具调用，记录“模型输出 → 参数解析 → 工具执行 → 结果回传 → 后续决策”。以项目中的 `[TOOL_CALL:...]` 格式为切入点，分析一次工具失败，理解 HelloAgents、MCP 与高德服务的边界。

**验收标准**：能解释 Agent 如何选择工具、获取结果和停止；能定位并修复一个工具调用问题，同时保持项目要求的调用格式。

### 阶段 5：多 Agent 编排

**学习内容**：职责拆分、上下文与数据传递、步骤依赖、串行与并行、失败传播和调用成本。

**代码入口**：`backend/app/agents/trip_planner_agent.py` 及其调用方。

**实践任务**：根据实际代码整理各 Agent 的输入、输出和依赖关系，区分独立查询和依赖前序结果的步骤。选择一个小流程调整，比较结果质量、耗时和调用次数。

**验收标准**：能解释当前拆分的收益与代价，说明哪些步骤可以并行，以及某一步失败后如何影响最终行程；调整结论有对比记录支持。

### 阶段 6：可靠性与评估（重点）

**学习内容**：可替代的外部依赖、针对性测试、日志定位、有限重试、耗时分析、结果质量评估。

**代码入口**：前述路由、服务、Agent、数据模型与 `backend/tests/` 中实际已有的测试。

**实践任务**：整理少量固定旅行需求，覆盖常规、多日、约束较多和外部服务失败场景。业务逻辑验证尽量使用替代的模型或工具返回值，真实 API 联调用于确认集成行为。比较修改前后的日期一致性、景点真实性、路线合理性、约束满足情况、耗时和调用成本。

**验收标准**：能区分“HTTP 成功”“结构正确”和“行程合理”；至少完成一次有记录的修改前后对比，明确自动检查、人工判断及证据不足的部分。

### 阶段 7：部署与运行

**学习内容**：虚拟环境、依赖、环境变量、进程与端口、浏览器 API 地址、CORS、反向代理、服务管理和部署流程。

**代码入口**：`backend/run.py`、`backend/app/config.py`、`backend/app/api/main.py`、`backend/requirements.txt`、`frontend/package.json`、`frontend/vite.config.ts`、`frontend/src/services/api.ts`。

**实践顺序**：

1. 检查服务器系统与运行环境，创建服务器自己的虚拟环境并安装依赖。
2. 配置后端环境变量，手动启动并验证接口和外部服务调用。
3. 配置前端 API 地址与访问方式，完成真实行程生成和地图检查。浏览器中的 `localhost` 指向访问者电脑；前端构建时环境变量的生效时机也需要确认。
4. 理解请求链路后，配置服务管理和必要的反向代理，验证重启与日志查看。
5. 将验证过的步骤整理为一键部署脚本，再接入 GitHub Push 自动部署，理解部署失败的处理与版本恢复。

**验收标准**：手动阶段能跑通完整请求并定位故障；服务化阶段能验证进程重启与恢复；自动部署阶段能验证版本更新与失败处理。分别记录验收结果。

## 实践与记录方式

每次实践遵循：提出问题 → 阅读相关代码 → 做一个小改动 → 验证结果 → 写入学习日志。

- 修改前明确问题、预期行为和验证办法，控制在一个可解释的小目标内。
- 记录原有行为、原因、修改依据、验证命令及实际结果；失败尝试同样有学习价值。
- 达到阶段验收标准后，在本计划更新进度并链接对应日志，不以“读过代码”代替掌握。
- 功能或修复与对应日志按 `AGENTS.md` 的规则组织；提交和推送分别等待用户明确指令。

| 文档 | 职责 |
| --- | --- |
| `docs/learning-plan.md` | 学习目标、范围、顺序、验收标准与进度 |
| `docs/learning-log.md` | 每次实践的问题、原因、方案与验证结果 |
| `README.md` | 项目介绍、运行说明与学习文档入口 |
