## 功能实现的小步拆分（已授权分批实施，2026-10-10）

目标是每步只增加一种可独立检查的行为，有明确输入、输出及结束条件；一次实现、验收和提交只覆盖表中一个最小子项。这里的先后是开发顺序，不将旅行运行时的任务依赖写死。沿用现有HelloAgents、planning_v4契约、MCP适配和观测能力，不引入新智能体框架或通用工作流平台。完整产品尚未交付，默认v3入口在v4端到端验收前保持兼容。

### 每步怎么验收与定位

- 共用一份上海三日合成需求，但各阶段使用自己的最小脱敏输入/输出样例。上一步的事实可固定输入下一步；复查F07无需重复请求模型与MCP。只增加本步需要的测试入口，不先建设通用回放平台。
- 程序规则按确定结果验收；模型输出按用户明确条件、事实引用、日期覆盖及结束条件验收，不要求两次输出同一套文字、地点顺序或串并行完全一致。查询质量、需求理解、排程和计算的失败分别记录，不能只留下总任务失败。
- 模型/工具接入步骤先做可控替身与相应异常，再按当步范围做有限真实核验；非接入步骤不反复跑整趟真实规划。全过程复用现有观测记录调用、耗时、Token、来源、阶段/任务/日期与错误；不先建设新观测页面。
- 每步完成后审查差异、执行相关验证、更新本Change及学习日志；明确用户接受状态，按用户授权独立提交。若出现回归，修复当前步再扩展，不同时叠加提示词、缓存、并发及界面改动。

#### F02 日期与时段规则状态

- 新增纯转换服务与固定上海三日样例测试。服务接收TripRequest、RequirementSummary、RuleSet及结构化边界输入，生成连续日期和六个SlotConstraint；PlanningInput.boundary_facts保留本次实际采用的缓冲值/来源、已核实day_ready_at、到达乐观起点和离开日活动结束乐观上界，并支持旧fixture省略该字段；不生成活动、不推算候选地点路线，也不接入正式v3入口。
- 到达/离开日期按请求时区生成；到达边界按左闭右开归类。餐次按可用时间和默认1小时独立判断。离开日先按“日开始至departure_at减缓冲”的乐观上界检查3小时；仅上界不足时整日跳过。返程路线未知时available_end保留为空，受边界影响的时段标conditional。required只表示该时段应被覆盖，不表示已验证时间或交通可行。
- 已核实day_ready_at可覆盖到达时刻上界；缺少该值时DayConstraint.available_start保持为空，并保留首个可能时段且标conditional，避免把原始到达时刻当成实际就绪时刻。规则服务不接收候选地点返程耗时，后续具体路线冲突留给F07/F08处理。
