## 1. 问题描述

显式子进程环境不能保证从 PATH 找到 uvx，地图工具发现失败。

## 2. 排查过程与原因判断

以下迁移原学习日志“问题 006：MCP 子进程找不到 uvx”的完整问题记录。带日期的实现、调用、测试和Git状态是历史事实；后续变更以当前状态入口为准。原记录未列出的复现步骤或尝试不补造。

<details>
<summary>排查、实现与验证证据</summary>

#### 原因与修改

MCP 工具启动时使用显式环境变量，子进程可能无法从 `PATH` 找到 `uvx`，导致地图工具发现失败。启动命令现在优先使用当前 Python 旁边可执行的 `uvx`，再检查 `~/.local/bin/uvx`，最后查询 `PATH`；均不存在时明确报错，不将空工具集合当成成功。

#### 验证记录

模拟 `PATH` 无 `uvx` 且虚拟环境中无 `uvx` 的场景，确认使用本地可执行文件；后端 84 项 unittest 全部通过（含 MCP 工具注册测试）。此测试不替代用户本地启动后对真实高德服务的验收。

---

</details>

## 3. 尝试方案与方案结果

依次检查 Python旁、本地安装及 PATH 中的可执行文件；84项历史测试通过。

## 4. 解决结果与验证边界

可执行路径查找和空工具拒绝已验证；真实服务可用性另验。

## 5. 经验总结

先核对实际子进程环境，不能把空工具集合当初始化成功。
