# ISSUE-029：单个坏活动导致整份正常安排丢失

- 整理日期：2026-10-11
- 记录状态：离线修复通过并合并；在线仍有缺项
- 范围：问题复盘；下方测试结果均为原记录中的历史证据，本次未重跑。
- 当前实现、验收及交付状态：[README](../../README.md)与[CHG-003](../changes/CHG-003-planning-performance-observability.md)；历史v3范围另见[CHG-002](../changes/CHG-002-trip-plan-enhancements.md)。

## 1. 问题描述

候选引用或活动字段只错一项，整份重生成会改变正常内容。

## 2. 排查过程与原因判断

以下迁移原学习日志“初版局部修复与保留有效安排（2026-10-11）”的完整问题记录。带日期的实现、调用、测试和Git状态是历史事实；后续变更以当前状态入口为准。原记录未列出的复现步骤或尝试不补造。

<details>
<summary>排查、实现与验证证据</summary>

- 原因与取舍：模型可能只写错一项候选引用或活动字段，整份重生成会改动正常安排。后端把能可靠定位的坏活动隔离，反馈具体条件和可用候选，只合并对应活动的替换；失败则在该位置提示，空缺交给原按日补查。未知日期、身份和损坏事实仍拒绝。截断、格式及活动修复共享一次额外调用，防止层层重试扩大成本。
- 审查发现：结构、引用和候选适用性校验可能依次暴露错误；先剥离至剩余安排完全通过，再统一请求修复。重复修复指令拒绝，正常活动及跨时段重复景点保持；同一时段还有正常活动时只提示初版活动被排除，不虚报整个时段缺项。
- 验证入口：`backend/tests/test_daily_plan_generator.py`覆盖修复反馈、保护正常安排、安全观测及预算；`backend/tests/test_daily_plan_recovery_pipeline.py`用合成上海三日验证真实F06与F09状态机交付预览；`frontend/tests/v4PreviewMapper.test.mjs`验证位置提示。完整离线结果与交付状态统一见[CHG-003](../changes/CHG-003-planning-performance-observability.md#v4-local-plan-repair)，没有重跑原任务或调用真实模型/MCP。

</details>

## 3. 尝试方案与方案结果

先隔离可定位坏活动，再一次定向修复；失败转缺项并保留正常活动；581项完整回归通过。

## 4. 解决结果与验证边界

活动级恢复已验收；不保证补查修订成功或最终信息完整。

## 5. 经验总结

局部错误应有局部恢复范围，身份和来源损坏不能套用该策略。
