# ISSUE-017：未知费用被模型输出为整个 null 对象

- 整理日期：2026-10-11
- 记录状态：历史修复与两次真实样本已验证
- 范围：问题复盘；下方测试结果均为原记录中的历史证据，本次未重跑。
- 当前实现、验收及交付状态：[README](../../README.md)与[CHG-003](../changes/CHG-003-planning-performance-observability.md)；历史v3范围另见[CHG-002](../changes/CHG-002-trip-plan-enhancements.md)。

## 1. 问题描述

qwen3.7-flash一日、三日初稿及修复均将必需费用对象写为null。

## 2. 排查过程与原因判断

以下迁移原学习日志“提示词补齐JSON输出示例（2026-10-09）”的完整问题记录。带日期的实现、调用、测试和Git状态是历史事实；后续变更以当前状态入口为准。原记录未列出的复现步骤或尝试不补造。

<details>
<summary>排查、实现与验证证据</summary>

- 问题与原因：真实单次基准的费用对象为null，结构修复仍失败。当前RouteTripPlanner提示词只传Schema，没有具体JSON示例；“查不到时留空”没有区分金额为空和整个对象为空，同名reference_cost在住宿与活动上的可空规则也不同。用户要求各阶段结构都补充示例。
- 修改与取舍：在`backend/app/agents/route_planner.py`补充首次搜集、后续景点/住宿餐饮查询、停止查询、初步/最终排程的完整示例，以及用户住处无法定位、空白日和未知费用字段值的子结构示例。修改角色沿用完整草稿示例，结构修复沿用相同系统提示并补充明确费用示例。区分必需对象、可空字段、空列表与有默认值的可省略字段，消除费用和住宿“留空”的歧义；示例地点为明确标注的虚构占位，实际地点仍只能取本次地图候选。保持公共数据契约与费用查询规则，不把未知价格当零，不增加应用层重试次数。
- 技术验证：新增`backend/tests/test_prompt_examples.py`，直接解析提示词中的JSON并用对应Pydantic模型校验，检查各活动类型、费用未知、自由活动、空白日和用户住处；重现住宿费用对象null路径，用模型与地图替身验证搜集、排程、一次结构修复和行程修改的实际消息都包含合法示例。执行README后端命令，98项测试通过；收尾将修复提示的住宿/活动费用示例拆成明确字段值后，相关4项测试再次通过。`git diff --check`通过。
- 运行与边界：确认没有活动规划任务后正常重启dev.py服务，后端`/health`返回healthy、前端Vite启动成功。没有追加真实模型或地图请求；替身验证不代表qwen3.7-flash已遵守新提示，也不能证明稳定提速，新增示例对实际耗时的影响未验证。既有失败报告与代码哈希保留，未提交或推送。CHG-003已同步范围与技术状态，工作区INDEX现有入口仍适用。

## 3. 尝试方案与方案结果

仅Schema与一次修复未成功；补各阶段合法JSON示例，区分对象必填和金额可空；98项测试通过。

## 4. 解决结果与验证边界

后续两次真实基准避免了该结构错误，仍有缺晚餐，不保证所有输出合法。

## 5. 经验总结

示例必须和运行时契约一致；金额未知不等于容器对象可空。
