# ISSUE-014：一日往返因住宿参考点缺失而整体失败

- 整理日期：2026-10-11
- 记录状态：历史修复与真实样本已验证
- 范围：问题复盘；下方测试结果均为原记录中的历史证据，本次未重跑。
- 当前实现、验收及交付状态：[README](../../README.md)与[CHG-003](../changes/CHG-003-planning-performance-observability.md)；历史v3范围另见[CHG-002](../changes/CHG-002-trip-plan-enhancements.md)。

## 1. 问题描述

模型将推荐住宿区域 place 留空，一日无住宿夜数仍被阻断。

## 2. 排查过程与原因判断

以下迁移原学习日志“本地真实规划验收：住宿参考点缺失（2026-10-03）”的完整问题记录。带日期的实现、调用、测试和Git状态是历史事实；后续变更以当前状态入口为准。原记录未列出的复现步骤或尝试不补造。

<details>
<summary>排查、实现与验证证据</summary>

- 问题：从首页提交北京一日行程后，任务实际完成候选搜集、地图查询和最终排程，但 `validation.itinerary_v3` 因模型将推荐住宿区域的 `place` 留空而失败。当天往返没有住宿夜数，也不应因此阻断整份行程。
- 修改：最终排程提示明确要求从已核实住宿候选选择区域参考点；后端在模型遗漏时按区域名称匹配及行程距离从已核实候选补足。没有住宿候选的一日往返允许参考点为空；过夜行程仍要求已核实参考点，用户指定住处的处理保持原有规则。
- 验证：新增有住宿候选、无住宿候选的一日行程回归；后端 86 项测试通过。重启本地后端后，从首页真实提交北京一日行程，任务成功保存 v3 结果（1 天、5 项活动、4 段路段），首页自动进入结果页；观测页可查看成功调用树及工程指标，记录完整。公共交通的部分路段仍无可用耗时，页面明确显示未知并提供已查询到的步行或骑行耗时。
- 展示复核：结果页曾按钟点将景点误标为“午餐”、用餐误标为“下午”；现按活动类型和时刻显示，浏览器确认五项活动标签正确。前端 `npm run build` 通过，保留已有主包体积提示。启动日志中的 Pydantic、FastAPI 和 Authlib 弃用提示不影响本次启动与规划。

</details>

## 3. 尝试方案与方案结果

从已核实候选补参考点；无候选的一日往返允许空，过夜仍严格核实；86项测试与一次真实任务通过。

## 4. 解决结果与验证边界

历史v3一日结果成功；部分公交仍未知。

## 5. 经验总结

条件校验应依据是否过夜，不能为可选信息丢弃整份有效结果。
