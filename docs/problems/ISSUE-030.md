## 2. 排查过程与原因判断

<summary>排查、实现与验证证据</summary>

- 问题：后续获授权的同配置新任务能够打开预览，但补查后的具体安排仍严重缺失。保留有效安排解决了整份丢弃的问题，并未证明单日修订能被正确采用。
- 证据缺口：`day_repair_service.py`生成每轮`attempts`，记录修订、重算等失败的安全错误码；`planning_v4_pipeline.py`只使用其最终草稿和报告，没有持久化这些记录。输出Schema通过及交通调用成功，均不能替代“修订已应用”的验证。
- 下一步取舍：先补齐每轮结果观测，用离线组合复现修订到重算再合并的实际边界。在线结果、调用量和原证据保护统一见[CHG-003](../changes/CHG-003-planning-performance-observability.md#v4-local-plan-repair)；本轮没有再次重试或修改修订逻辑。
