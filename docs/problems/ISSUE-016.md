# ISSUE-016：聚合耗时图无法解释执行先后与并行关系

- 整理日期：2026-10-11

- 当前实现、验收及交付状态：[README](../../README.md)与[CHG-003](../changes/CHG-003-planning-performance-observability.md)；历史v3范围另见[CHG-002](../changes/CHG-002-trip-plan-enhancements.md)。

## 1. 问题描述

累计条形图无法展示实际调用时间关系，未知Token容易误解为零。

## 2. 排查过程与原因判断

以下迁移原学习日志“Agent观测正式页改版（2026-10-09）”的完整问题记录。带日期的实现、调用、测试和Git状态是历史事实；后续变更以当前状态入口为准。原记录未列出的复现步骤或尝试不补造。

<details>
<summary>排查、实现与验证证据</summary>

- 问题与取舍：首版聚合条形图无法直接看出规划步骤先后和并行关系，用户认可调用树＋瀑布时间线原型后批准开发。正式页默认轨迹，并接入逐次Token、工具统计和异常列表；四视图共用选中调用的真实脱敏详情。异常总数以失败和中断为子项，父级步骤不重复计数；未知用量不补零，累计调用时间不冒充任务总耗时。
- 实现：摘要只增加既有三个可空Token字段，不增加正文或数据库列。纯转换处理循环、孤儿、时间边界和筛选上下文；页面按任务和请求版本隔离迟到响应，详情懒加载，运行中只轮询状态/摘要。首版重复图表代码移除；用户接受正式页后删除临时HTML原型。
- 证据：后端94项unittest、前端53项边界断言和类型/生产构建通过，500kB主包提示保留。真实历史成功/中断记录、1440px桌面及390px手机已核对；合成API检查活动到终态、请求竞态、404/503恢复、零值/缺失/仅总量/截断及文本转义。现行回归检查清单见[工程指标设计](../engineering-metrics-design.md#验收清单)。
- 边界：未生成新规划、未核对真实供应商usage或优化性能；用户已接受正式页展示，但未逐项报告原AC-016的三项手工操作。无活动任务时重启本地开发服务以加载摘要变更，不作为日志/持久化专项验收；未部署。
- 代码与测试：`frontend/src/views/Observability.vue`、三个`Observation*.vue`组件、`frontend/src/services/observationView.ts`、`frontend/tests/observationView.test.mjs`、`backend/app/services/task_repository.py`及`backend/tests/test_metrics.py`。

- 历史数据核对：成功样本90条记录、模型5次/工具70次、总Token58,318，布局246.4秒与最终生成222.5秒分别可定位。中断样本111条记录，异常15次=失败14次＋中断1次，总耗时未知；真实失败公交工具详情保留TimeoutError。
- 合成场景：输入20、输出40、供应商总量99独立展示；零、缺失、仅总量与截断preview均有不同提示，带HTML标签的输入没有生成img节点。50条分页、状态筛选、四视图刷新与前进/后退、成功结果入口均检查；快速切任务及切详情不串数据。指标503、详情404、摘要/列表/状态503恢复有效，任务404清空其数据。
- 轮询证据：活动任务状态/摘要每2秒更新，metrics请求0次、自动初始详情1次；终态metrics只读取1次、详情仍1次，并保留工具视图。终态running、accepted、循环与孤儿记录、重叠10秒父阶段/两次7秒调用、工具10ms/30ms/未知的20ms平均由纯数据测试覆盖。

## 3. 尝试方案与方案结果

采用调用树与瀑布时间线，按版本隔离迟到响应；94项后端、53项前端及浏览器验证通过。

## 4. 解决结果与验证边界

展示已获用户接受；不表示真实供应商usage专项或性能优化已完成。

## 5. 经验总结

累计调用耗时不等于任务总耗时，未知用量必须保留未知。
