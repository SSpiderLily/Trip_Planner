# ISSUE-025：初始派发失败丢弃此前有效事实

- 记录状态：离线修复已验证并合并
- 范围：问题复盘；下方测试结果均为原记录中的历史证据，本次未重跑。
- 当前实现、验收及交付状态：[README](../../README.md)与[CHG-003](../changes/CHG-003-planning-performance-observability.md)；历史v3范围另见[CHG-002](../changes/CHG-002-trip-plan-enhancements.md)。

## 1. 问题描述

一次无效派发让已经取得的63个地点事实未能进入预览。

## 2. 排查过程与原因判断

以下迁移原学习日志“区分派发拒绝与已有事实损坏（2026-10-11）”的完整问题记录。带日期的实现、调用、测试和Git状态是历史事实；后续变更以当前状态入口为准。原记录未列出的复现步骤或尝试不补造。

<details>
<summary>排查、实现与验证证据</summary>

- 问题：主智能体一次无效派发不应让此前成功查询的事实一起失效。Pipeline之前将初始technical_error统一抛出，实际收集到63地点事实仍未生成预览。
- 修改：`PlanningDispatchService.validate_result_snapshot`复用事实、候选、任务和区域校验；Pipeline仅接收安全快照，并把提前结束提示写入最终报告与观测。真正身份/来源错误继续拒绝；不放宽餐饮绑定规则。
- 根562项回归通过；实际快照的离线回放到达三日预览。在线续验的状态统一见CHG-003，不把受控模型结果当作真实排程验收。INDEX导航入口保持有效；临时事实、数据库、模型配置不提交。

</details>

## 3. 尝试方案与方案结果

复用身份、来源和候选校验，仅用安全部分快照继续；562项回归与离线预览通过。

## 4. 解决结果与验证边界

有效快照可保留；来源或身份损坏仍终止。

## 5. 经验总结

控制决策失败不自动说明历史查询事实失效。
