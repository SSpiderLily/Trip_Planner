# ISSUE-021：编辑后重启会遗留 pending 或遗漏待查日期

- 记录状态：离线组合验证通过

## 1. 问题描述

重算仅存在内存中，进程重启或跨日继续编辑可能丢失任务。

## 2. 排查过程与原因判断

以下迁移原学习日志“编辑持久化与后台重算恢复（2026-10-11）”的完整问题记录。带日期的实现、调用、测试和Git状态是历史事实；后续变更以当前状态入口为准。原记录未列出的复现步骤或尝试不补造。

<details>
<summary>排查、实现与验证证据</summary>

- 问题：只在内存安排重算会让重启后的预览永远pending；跨日继续编辑会遗漏上一天未完成路线。`PlanningV4PreviewEditService`与PreviewRepository把编辑、幂等收据和路线任务放入同一事务，新任务继承尚未完成日期，后台发布检查计划、计算标识和存储版本。
- 根审查修正：已提交编辑/还原不能因调度故障报失败；丢失worker的running任务可恢复。已核实返程端点贯穿编辑、重算与时间汇总，避免编辑后丢失返程段；已取消路线上下文按日期替换，技术截止仍限制总等待。每次重算通过安全span归属原任务，观测故障不阻断用户操作。
- 根验收：组合545项后端检查通过；上海既有三日事实进入实际API、SQLite和F08（外部路线替身失败），新增重复景点→重排→删除一次→清空当天，版本1至5，其他日保持不变、缺项保留、pending终结，重放不重复应用；重启后内容仍在，最终结果只经显式save建立。离开日固定测试核对20分钟交通加1小时缓冲。并行修改、调度/发布/工厂异常、重启及观测归属均有独立回归。
- 边界：零新增真实模型/MCP调用，未改正式库；页面及搜索继续分步验收。README、CHG-003和设计页同步；INDEX沿用既有入口，临时日志不提交。
