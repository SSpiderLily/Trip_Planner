# ISSUE-042：规划耗时过长，组合优化未取得合格提速

- 整理日期：2026-10-11
- 记录状态：性能实验失败并撤回；稳定提速仍未验收。
- 范围：2026-10-09的旧规划器基线与R1—R3实验，不作为当前v4耗时基准。

## 1. 问题描述

真实规划需要数分钟，模型排程是当时样本的主要耗时来源。缩减输出和上下文、按角色配置思考后，部分任务更快结束，但缺餐、漏必去或类别错误使质量门槛未通过。

## 2. 排查过程与原因判断

先读取调用树并只累计叶调用，再固定请求和模型建立单独基线。区分正常交付、失败提前返回和人工质量复核；不将不同模型、缺项程度或流程长度混成等价性能对照。

## 3. 尝试方案与方案结果

| 尝试 | 结果与结论 |
| --- | --- |
| qwen3.8-flash基线 | 3/6次后暂停；成功样本模型约占80%，完整基线不足。 |
| qwen3.7-flash原提示基线 | 一日217.753秒、三日159.080秒均因费用对象null失败，不能当提速。 |
| 补JSON示例后的基线 | 一日254.159秒、三日274.092秒成功；三日缺晚餐，质量仍有限。 |
| R1—R2组合优化 | 住宿、必去及餐饮类别问题阻断质量验收；较快终态不能证明有效提速。 |
| R3取消思考预算 | 补充人工时刻核对后质量0/2通过；三日完整耗时比基准增加6.04%。 |
| 撤回组合优化 | 恢复优化前代码并保留JSON示例；98项回归、关键源码哈希及数据库副本兼容检查通过。 |

## 4. 解决结果与验证边界

用户要求撤回组合实验，未获得合格稳定提速。撤回范围包括实验期间的住宿来源、缺餐反馈等代码修正，因此“曾修复”不能当作撤回后仍有效。后续v4另行实现，现行范围以[CHG-003](../changes/CHG-003-planning-performance-observability.md)为准。

## 5. 经验总结

先固定质量门槛，再比较完整流程耗时。每次实验保留配置、源文件哈希、调用统计和回退结论。调用减少不保证供应商等待减少，单次样本不能建立因果关系。
